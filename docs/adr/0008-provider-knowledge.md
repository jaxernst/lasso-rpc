# Local provider knowledge

Status: accepted.

Core keeps its existing head-evidence admission and ordering rules for ordinary
selection. Recovery-specific head suitability remains separate from learned
provider limits.

RPC routing reads bounded local state. A dispatched attempt enqueues a body-free
record on the existing projection dispatcher; pure learners reduce it away from
the request process. Method refusal, numeric log-span constraints and historical
depth change candidate order by default, within availability tiers. No hint can
remove the last candidate, override operator restrictions or grant more sends.

Learner keys use configured connection identity, registered methods and fixed
request-shape buckets. Codecs, retained evidence and queues have explicit bounds.
Current serving hints are reconciled before publication, expire without an
external lookup and can be withdrawn by newer accepted contradictory evidence.
Feedback loss is visible in lane counters; an unavailable learner leaves routing
available.

The standalone host owns the ETS tables for its lifetime. The default persistence
adapter applies observations locally. Core starts neither a durable knowledge
adapter nor image exchange. Restarting relearns from traffic. File profiles use
configured shared or isolated connection identities without account authority or
reset services. Historical and span recovery use subsequent request outcomes;
Core does not schedule idle retained-limit revalidation.

Opt-in request metadata exposes a bounded explanation with route ordinals instead
of internal route identities. Local diagnostics expose current attributed hints;
Prometheus exports only fixed-kind aggregate retraction and applied-deferral
counters. Deferral counts describe measured order changes, not prevented failures.

This uses the existing dispatcher and supervision owners. No independent request
queue, database, timer process or external interpretation service is required.
